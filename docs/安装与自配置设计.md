# jobfxxk 安装与自配置设计

> 2026-10-31 起草。目标是回答一个问题：**别人下载之后，说一句「用 jobfxxk 帮我投简历」，整个工作流就自己配好、自己跑起来。**
>
> 本文只做设计，不改代码。看完再决定做到哪一步。

---

## 0. 一句话结论

现在这份 jobfxxk 是**「作者本机能跑」的代码**，不是**「陌生人能用」的产品**。差距不在功能，在三个地方：装不上、配不动、缺东西没人补。功能那部分已经齐了——12 个脚本、11 个阶段、六份细则，全在。

---

## 1. 目标与不目标

**目标**：一个陌生 Windows 用户，有 Word、有 Node、有 Python，从下载到看见「可以开始投了」，不超过 10 分钟，中途只回答问题，**不编辑任何文件、不敲任何命令**。

**不目标**（写清楚，免得做着做着跑偏）：

- 不是跨平台。Mac 和 Linux 的兼容放到 P2，Windows 跑通之前不碰。
- 不是免依赖。Node、Python、Word 该装还得装，只是要装得明白。
- 不是全自动投递。提交按钮永远由用户点，这条不变。

---

## 2. 现状：八个会断的地方

我按一个陌生人从下载到投出第一份简历的顺序走了一遍，断在这八处。

| # | 断点 | 现在的实际行为 | 陌生人的反应 |
|---|---|---|---|
| 1 | 安装位置 | README 让人把文件夹放进 `C:\Users\名字\.claude\skills\`，这个目录多数机器上不存在 | 「放哪？」 |
| 2 | 数据目录 | `paths.py` 用 `os.path.dirname(REPO)` 推导，默认「与仓库平级」 | 装成 skill 后代码在托管目录，数据跟着进去，升级时可能被清掉 |
| 3 | config.json | 要手动复制 `config.example.json`，手填七条路径 | 填错一个反斜杠就报错，而且报错信息指向不明 |
| 4 | 简历 | 没告诉用户必须 docx 和 pdf **成对**提供 | 只给 PDF 的人，走到微调那步才发现做不了 |
| 5 | 依赖 | `check_config.py` 只报错，不修 | 「缺少 pypdf → 执行 pip install pypdf」，然后不知道在哪执行 |
| 6 | 浏览器 | 要先跑 `detect_browsers.py`，再把名字和路径**手工抄回 config.json** | 抄错一个字，投递时整个 browser.cjs 起不来 |
| 7 | 锚点 | 要手动跑 `make_anchors.py` | 不知道有这一步，微调直接失败 |
| 8 | 岗位库 | 首次同步 90 秒、翻译 40 秒，全程无输出 | 以为卡死了，直接关掉 |

八处里，1、3、6、7 是**纯粹的体验问题**，改文档和加脚本就能解决；2、4、5、8 是**结构问题**，要在设计层面定规矩。

## 3. 三条设计原则

**第一，文档不做配置，脚本做判断。** 现在 SKILL.md 里写满了「第一步复制，第二步改路径」。文档写给人看的，人不该在对话里照着文档改文件。所有判断收进 `setup.py`，文档只描述它返回什么。

**第二，脚本不擅自下载。** 装依赖要装一百多兆的东西，必须由 agent 问过用户再执行。脚本只负责**判断**和**给出可执行的动作**，不负责悄悄执行。

**第三，对话由状态机驱动，不靠模型临场发挥。** `setup.py --check` 输出一个明确的状态码，SKILL.md 里每个状态码对应一段固定动作。这样换个模型、换个会话，行为是一样的。

## 4. 安装层

### 4.1 产物形态：`jobfxxk.skill`

`.skill` 就是一个 zip，根目录放 SKILL.md，连同 references、scripts、assets 一起打进去。桌面版打开它会直接给「保存技能」按钮，点一下装进用户账号，全程不碰文件系统。

发布方式：GitHub Release 挂 `jobfxxk.skill` 作为附件，README 第一行给下载链接。仓库本身的 git clone 方式保留，给 Claude Code 用户。

### 4.2 两条通道，两套文档

| 用户类型 | 怎么装 | README 对应段落 |
|---|---|---|
| Claude 桌面版 | 下载 `.skill` → 双击/拖进去 → 点保存技能 | 放最前面，三步图 |
| Claude Code | `git clone` 到 `~/.claude/skills/jobfxxk` | 放第二段，给一行命令 |
| 只用脚本 | 下载 zip 解压，`python scripts/setup.py` | 放最后，给开发者 |

### 4.3 安装位置变了，数据目录就不能再推导

这是第 2 个断点的根因，必须单独说。

现在 `paths.py` 靠「代码在哪，数据就在它旁边」来找数据。把仓库 clone 到本地时成立，因为数据和代码在同一个父目录下。但装成 `.skill` 之后，代码落在应用托管的目录里，那个目录会随版本更新被替换——**用户的数据放在那里，升级一次就没了**。

所以数据目录的定位规则要改，按优先级：

1. 环境变量 `JOBFXXK_CONFIG`（给高级用户留的口子，保留现状）
2. `%USERPROFILE%\jobfxxk-data\config.json` ← **新的规范位置**
3. 与代码目录平级的 `jobfxxk-data/config.json`（兼容作者本机和 git clone 的旧布局）
4. 都没有 → 由 `setup.py` 在 `%USERPROFILE%\jobfxxk-data` 创建，并告诉用户位置

这样 clone 仓库的老用户走第 3 条继续有效，装成技能的陌生用户走第 2 条，互不干扰。

### 4.4 版本与更新

skill 根目录放一个 `VERSION` 文件。阶段 0 读本地版本，和 GitHub Release 的最新 tag 比（一次 HTTP，失败就跳过）。落后了就说一句「有新版本，要不要更新」，不强制。

更新不动数据目录——这是 4.3 设计出来的直接好处。

## 5. 自配置层：setup.py

这是整份设计里唯一真正新的东西，其余都是改造。

### 5.1 单一入口，幂等

```
python scripts/setup.py --check     # 只判断，不改任何东西，输出 JSON
python scripts/setup.py --apply X   # 执行某一项修复，X 来自 --check 的返回
```

同一条命令跑十遍结果一样。中断在任何一步，重跑都能接上。

### 5.2 接口契约

`--check` 的返回是给 agent 读的，不是给人读的：

```json
{
  "status": "needs_deps",
  "ready": false,
  "blocking": true,
  "ask": "还差 Playwright（自动填表要用，约 130MB）。要现在装吗？",
  "actions": [{"id": "install_playwright", "label": "装", "size_mb": 130}],
  "done": ["python", "node", "data_dir"],
  "missing": ["playwright", "edge"]
}
```

**字段约定**：`status` 是状态机的位置；`ask` 是可以直接念给用户的一句话；`actions` 是修好当前状态所需动作；`done` / `missing` 是给人看进度用的。agent 拿到 JSON 只做两件事——念 `ask`，然后等用户同意后跑 `--apply <id>`。

### 5.3 状态机

| status | 含义 | ask（念给用户） | 修复动作 |
|---|---|---|---|
| `no_python` | 没有可用 Python | 「这台机器没找到 Python，要先装一个」 | 给下载链接，人工 |
| `no_node` | 没有 Node | 「要装 Node.js，官网下载下一步到底」 | 给下载链接，人工 |
| `no_data_dir` | 没有数据目录 | 「我在 xxx 建一个放你资料的文件夹，行吗」 | `init_data_dir` |
| `no_resume` | 没找到简历 | 「把你的简历拖进来，Word 和 PDF 各一份」 | 用户提供 |
| `resume_pdf_only` | 只有 PDF | 「只有 PDF 我改不了字，要么给我 docx，要么先用模板顶着」 | `use_builtin_template` |
| `no_deps` | 缺 Playwright / pypdf | 「还差 xxx，约 N MB，要装吗」 | `install_*` |
| `no_office` | 没有 Word | 「没 Word 就没法导出 PDF，只能手动导」 | `pick_soffice`（P2） |
| `no_browser` | 没选浏览器 | 「第一次投递时我扫一下你装了哪些浏览器」 | `detect_browser` |
| `no_anchors` | 有 config 没锚点表 | 「量一下你简历的行宽，十几秒」 | `make_anchors` |
| `no_jobs` | 岗位库没同步或过期 | 「同步岗位库，大概一分半，别关窗口」 | `sync_jobs` |
| `ready` | 全部就绪 | 「可以开始了，你想投什么岗位」 | — |

状态之间有依赖：`no_data_dir` 在 `no_resume` 之前，`no_deps` 在 `no_anchors` 之前。`--check` 每次只返回**最靠前的一个**阻塞项，修完再查下一个。一次只问一件事，比一口气列八个问题体验好得多。

### 5.4 SKILL.md 阶段 0 怎么改

现在的阶段 0 是「读 state.json 和台账，给三行摘要」。改成先问脚本：

```
阶段 0 · 启动检查

1. 跑 python scripts/setup.py --check，拿到 JSON
2. ready=false → 念 ask，等用户回答，跑对应的 --apply，回到第 1 步
3. ready=true  → 读 jobfxxk-data/user/state.json 和投递台账，给三行摘要
4. 然后进阶段 1

不要跳过脚本自己判断环境。不要一次问两个问题。
```

原来的「第一次使用：三步配好」整节删掉，换成「装完之后第一次跑会发生什么」——纯描述，没有让用户动手的步骤。

### 5.5 简历怎么找

不让人填路径，靠猜 + 确认：

1. 扫 `~/Desktop`、`~/Downloads`、`~/Documents`，以及用户主目录下一层
2. 文件名含「简历 / resume / cv / 求职」的，收进来
3. docx 和 pdf 按文件名主干配对（去掉扩展名后相似度 > 0.8）
4. 找到 1–3 份候选，念给用户听：「是不是这份：某某 秋招简历.docx」
5. 配不上对、只有 PDF 的 → 走 `resume_pdf_only`

猜错了也不要紧，用户一句话就能改，比让人填绝对路径快。

### 5.6 锚点标定要改一处

`make_anchors.py` 现在只读 `pages[0]` 反推行容量。这对她那份单页简历没问题，但别人的简历两页、三页很常见，第一页往往是最宽的，会算偏。

改动：遍历所有页取每行字数，取众数而不是第一页的 90 分位。另外加一个**可信度**输出——如果满行样本少于 15 条，说明这份简历排版不规则（分栏、表格），就提示「你的模板行宽不统一，微调我会偏保守，长度控制在最短的那档」。

## 6. 依赖自愈

| 组件 | 怎么探 | 修复命令 | 体积 | 要问吗 | 失败降级 |
|---|---|---|---|---|---|
| Python | `sys.version_info` | — | — | — | 直接停，给下载链接 |
| Node | `node --version` | — | — | — | 直接停，给下载链接 |
| pypdf | `import pypdf` | `python -m pip install pypdf` | <1MB | 不用问 | 停：读不了 PDF 就没法标定 |
| Playwright | `node -e "require('playwright')"` | `npm install` | ~10MB | 要问 | 停：不能自动填表 |
| Chromium | `node -e "chromium.executablePath()"` | `npx playwright install chromium` | ~130MB | **必须问** | 用本机 Edge（已装就免下载） |
| Word | Word COM 探版本 | — | — | — | P2 接 LibreOffice |
| 浏览器 | 扫注册表和 Program Files | — | — | 不用问 | 用 Edge，Windows 自带 |

**Edge 优先**：Windows 10/11 自带 Edge，是 Chromium 内核，Playwright 可以直接驱动不用额外下载浏览器。所以默认路径是「用你系统的 Edge」，把 130MB 那个下载变成兜底而不是必需——这是把首次安装从五分钟压到一分钟的关键。

## 7. 降级矩阵

| 场景 | 行为 |
|---|---|
| 有 Word | 正常，Word COM 导出 PDF |
| 无 Word，有 WPS | 探 WPS 的 `KWps.Application`，多数版本兼容 Word COM 接口 |
| 无 Word 无 WPS | P2：LibreOffice `soffice --headless --convert-to pdf`。转换后版式可能微移，要复验页数和首末行 |
| 只有 PDF | 用 `assets/template/简历模板.docx` 起步，让用户填经历；或明确告知「只能投，不能微调」 |
| 简历内容在文本框里 | 检测 docx 的 `<w:txbxContent>`；有就提示「你的简历文字在文本框里，我改不了，改用模板」 |
| 断网 | 岗位库同步失败 → 明说失败并保留旧缓存，其余流程继续 |
| 路径含中文或空格 | 所有 shell 调用一律加引号。这条现在就有隐患，要全脚本过一遍 |

## 8. 首次会话长什么样

用户装好 skill，第一句话是「帮我投简历」。

> **我**：先看一下你的环境。（跑 setup --check）
>
> **我**：这台机器没找到 Node.js，装不了。官网 nodejs.org 下 LTS 版，一路下一步，装完回来说一声。
>
> **用户**：装好了。
>
> **我**：（重跑）行，还差一个自动填表要用的组件，Playwright，大约 10MB，不要紧。要我装吗？
>
> **用户**：装。
>
> **我**：（npm install，40 秒）装完了。现在找你的简历——我在桌面看到「某某 秋招简历.docx」和同名 PDF，是这两份吗？
>
> **用户**：是。
>
> **我**：（写 config，跑 make_anchors）量好了，你简历每行大概 50 字，24 个位置。第一次用要同步岗位库，大概一分半，别关窗口。（sync + translate）
>
> **我**：可以开始了。你想投什么岗位？

从「帮我投简历」到「可以开始了」，用户只说了三句话，没碰过一个文件。这是要验收的那条路径。

## 10. 验收标准

可以用一句话否掉任何一条：

1. 全新 Windows（有 Word、Node、Python），从点「保存技能」到看见「可以开始了」，**≤ 10 分钟**，用户回答问题 ≤ 5 次，未编辑任何文件。
2. 同一台机器再开一个会话，阶段 0 直接 `ready`，不重复问任何已答过的问题。
3. 无 Word 的机器，给出明确替代路径，不崩、不假装成功。
4. 只有 PDF 的用户，能走到「用模板起步」，不是走到微调才失败。
5. 断网时岗位库同步失败，其他步骤照常。
6. 任何一步中断，重开会话能从上一步接着走，不从头来。

## 11. 风险与未决

**装成 `.skill` 之后脚本还能不能执行**——技能装在应用托管目录里，脚本可能是只读的、路径可能带中文和空格。这一条必须先在真机上验证，验证不通过，整个方案要退回「让用户 clone 仓库」。**这是 P0 的前置条件，不是收尾项。**

**Word COM 在受限账户下未必能用**。有些企业机禁了 COM 自动化，表现出来是导出 PDF 静默失败。要加超时和明确的失败信息。

**飞书岗位表随时可能失效**。现在链接写死在 `sync_jobs.cjs` 里，维护者一改表结构就全断。要加「同步到 0 条」的显式报错，而不是静默成功。

**版本更新时的数据迁移**。现在 VERSION 1 简单，`config.json` 加字段的话老配置要能兼容读。

## 12. 分期

**P0 · 最小闭环**（做完就能自己拿一个新账号试）
`setup.py`（只做 check + init_data_dir + 写 config + make_anchors + 读简历）+ 重写 SKILL.md 阶段 0 + 打 `.skill` + 验证它在托管目录里能不能跑。
验收标准第 1、2 条。

**P1 · 依赖自愈与浏览器**
install_* 动作、Edge 优先、简历配对优化。
验收标准第 3、5 条。

**P2 · 跨平台与降级**
soffice 兜底、文本框检测、WPS 探测。
验收标准第 4、6 条。

**P3 · 发布自动化**
GitHub Actions 打 tag 出 `.skill`、版本比对提示。
