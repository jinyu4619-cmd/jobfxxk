# 投递台账规范 v1.1

> 触发：**每次投递成功之后**自动更新
> 定位：投了哪家、到哪一步、还来不来得及，一眼要能看清
>
> v1.1 改动：与 `scripts/write_tracker.py` 的实际行为对齐。以前这里写的是「md + json 双份同源、三段分表」，脚本从来没这么做过——表格是脚本整表重排的，表格之外的内容原样保留。

---

## 一、什么时候写

| 时机 | 动作 |
|---|---|
| 投递前（阶段 5 定完志愿） | 写一条 `待投递` 草稿，记录目标岗位与简历版本 |
| **用户点提交、系统返回成功页 / 能查到申请** | 用 `--update` 把状态改成 `已投递`，补齐日期、入口链接、内推码来源 |
| 提交失败（校验不过、被拦截、超时） | **不写入台账**，记录失败原因，交由用户重试 |
| 收到测评/笔试邀请 | 状态改为 `测评/笔试`，下一步写截止日 |
| 收到面试邀请 | 状态改为 `面试中`，同时在面试台账里开一条 |
| 收到拒信 / 流程终止 | 状态改为 `已终止`，记终止阶段 |
| 拿到 offer | 状态改为 `offer` |

**判定「投递成功」的唯一标准**：系统页面明确出现成功提示，或投递记录里能查到这条申请。**看到提交按钮变灰、页面跳转，都不算成功**，必须以能查到的记录为准。

---

## 二、存储

**一个文件，一张表。** 位置取自 `config.tracker`（默认是投递跟踪目录下的 `投递台账.md`）。

- 表格部分由 `write_tracker.py` 整表重排，不要手工编辑单元格
- 表格之外的内容（你自己加的备注、链接、小节）**原样保留**，脚本只替换表格和顶部那行统计

以前的「投递台账.json」已经取消，别再造第二份，否则两边一定会不一致。

---

## 三、字段

脚本维护 11 列，多一列少一列都由脚本决定：

| 列 | 必填 | 说明 |
|---|---|---|
| # | 自动 | 自增，不重用 |
| 公司 | 是 | 全称 |
| 岗位 | 是 | 系统里的原始名称，不改写 |
| 城市 | 否 | 工作地点 |
| 投递日期 | 自动 | 写入当天 |
| 简历版本 | 否 | 文件名或版本名，如「微调版」 |
| 内推码 | 否 | 实际填入的码，没用写「未使用」 |
| 内推码来源 | 否 | 用户提供 / 飞书表 / 未使用 |
| 状态 | 是 | 见第四节 |
| 下一步 | 否 | 一句话，如「等测评通知」「10-30 前完成测评」 |
| 链接 | 否 | 实际投递的页面地址 |

**派生统计**（脚本自动算，写在表格上方那一行）：累计投递 / 待投递 / 在流程中 / 已终止 / offer。分项加起来一定等于总行数，对不上说明有状态写歪了，脚本会把认不出的状态算进「已终止」并保持总数自洽。

---

## 四、状态机

```
待投递 → 已投递 → 筛选中 → 测评/笔试 → 面试中 → offer
                     ↘         ↘          ↘
                      已终止   已终止     已终止
```

规则：

- **只能向前推进**，不能回退（写错了改下一步，不改状态）
- 「已终止」是终态，之后不再更新
- 状态名必须是这七个之一：`待投递` `已投递` `筛选中` `测评/笔试` `面试中` `offer` `已终止`。写别的会被脚本拒绝——这是故意的，避免同一件事出现三种写法

---

## 五、与「投递跟踪总表」的分工

如果你还有一张自己维护的总表（历史累计、手写备注、分档），**两张表各管一段，不要互相复制**：

- 总表：投递之前的历史，人工维护，脚本不碰
- 投递台账：从装上这套工具之后自动记的流水

一旦发现同一家公司同时出现在两张表里且说法不一致，以台账为准（它有时间戳和链接）。

---

## 六、与面试台账的分工

- 投递台账：只管到「进了面试」这一步，记公司、岗位、状态
- 面试台账：记录每一场的轮次、形式、结果、评级、复盘要点

两张表通过「公司 + 岗位」关联，不重复记同一件事。

---

## 七、写入纪律

1. **只记录事实**，不写推测（"感觉能过"不写）
2. **一律用脚本写**，不要手搓表格——手搓的格式和脚本解析的不一致，下一条就会覆盖掉
3. **每次投递只写一行**，重复投同一岗位新建一行，备注里写「二次投递，原记录 #N」
4. **失败不记账**：提交没成功的，不进主表，避免污染统计
5. 要在表格外补充说明（比如 HR 说 11 月统一筛），写在表格**下方**，不要改表内的行

---

## 八、交付给用户的内容

每次投递完成后，**只交付两样**：

1. **更新后的投递进度**（新增的那一行 + 更新后的统计）
2. **状态如实标注**——用户提供了后续进展就按实际写；**没提供就写「已投递」，不推测、不预设**

---

## 九、异常处理

| 异常 | 处理 |
|---|---|
| 提交后页面报错但无明确提示 | 去投递记录页确认是否已生成申请；确认不到则判定失败 |
| 投递成功但入口链接失效 | 记公司+岗位，链接留空并备注 |
| 同一岗位重复投递 | 新建行，备注「二次投递，原记录 #N」 |
| 用户投完又撤回 | 状态改「已终止」，下一步写「本人撤回」 |
| 测评邀请邮件未收到 | 状态保持「已投递」，下一步写「待测评邀请」，7 天后提醒用户查邮箱/垃圾箱 |
