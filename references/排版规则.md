# 排版规则 v1.0

> 数据来源：`张三 27秋招 - 某消费品公司.pdf` 实测（pypdf 坐标解析）
> 适用：中文校招简历，单页，单栏 + 右对齐时间列

---

## 一、页面骨架

| 项 | 值 | 说明 |
|---|---|---|
| 纸张 | A4 595 × 842 pt | 不允许横向或 Letter |
| 上边距 | 62 pt | 姓名基线到页面顶端 |
| 下边距 | ≥ 40 pt，目标 52 pt | 低于 40 会显得拥挤，高于 90 说明版面没填满 |
| 左边界 | 50 pt | 正文起始 x |
| 右边界 | 545 pt | 日期右端对齐线，偏差 ≤ 2 pt |
| 正文可用宽度 | 495 pt | 9pt 字号下约 55–60 个汉字/行 |

**一页是硬约束。** 溢出即失败，必须回退内容，不允许交付两页（例外：用户明确同意）。

---

## 二、字号层级（只允许这六个）

| 层级 | 用途 | 字号 | 字重 |
|---|---|---|---|
| L1 姓名 | 页首 | 20 pt | 粗，字间距 +2 |
| L2 区块标题 | 教育背景 / 实习经历 / 项目经历 / 校园经历 / 个人总结与专业技能 | 10.6 pt | 粗，下加浅蓝细线 |
| L3 条目头 | 学校名、公司名、项目名 | 9.5 pt | 粗 |
| L4 职位/专业 | 条目头同行的第二列 | 9.5 pt | 粗 |
| L5 时间 | 条目头同行的右列 | 9.5 pt | 粗 |
| L6 正文 | bullet 内容、顶部联系方式 | 9.0 pt / 10.0 pt | 常规 |

**规则：不得新增字号。** 需要强调时只能加粗或调整措辞，不允许改字号或改颜色。字号一多版面就散。

---

## 三、行距与呼吸

| 间距 | 值 | 适用 |
|---|---|---|
| 正文行距 | 14 pt（固定值，非倍数） | bullet 内部换行 |
| 条目之间 | 16 pt | 公司 A 结束 → 公司 B 开始 |
| 区块之间 | 19 pt | 实习经历结束 → 项目经历标题 |

**禁止**：连续两个空行；用空行凑版面。所有间距由段落格式控制，不靠回车。

---

## 四、区块顺序（固定）

```
姓名（L1）
联系方式（一行：出生年月 | 邮箱 | 电话 | 政治面貌 | 语言 | 奖学金）
教育背景
个人总结与专业技能
实习经历
项目经历
校园经历
```

技能区块**刻意放在教育背景之后、实习经历之前**——HR 扫读时先看到能力标签，再看到佐证。不要挪到最后。

---

## 五、各区块内部结构

### 5.1 教育背景

**一行式，不拆分。** 每所学校占一行：学校名（含 985/211 标注）| 学历与专业 | 起止时间。

学校行的**下一行**放该校期间的获奖与竞赛，可多条，字号 L6：

```
某师范大学(211)      某某学硕士（27届）      2024.09-2027.06
2024 与 2025 年某师范大学校级奖学金
某财经大学           某某学学士             2019.09-2023.06
全国大学生某某学科竞赛 省级奖项（队长）
```

**为什么不拆两行**：学历和奖项绑定在同一视觉块里，信息密度更高；拆开每所学校要多占一行，五所学校的模板会直接溢出。

**注意**：网申系统常要求单独填「学院名称」，简历正文不写，但信息档案里必须有。

### 5.2 实习经历

- 条目头三列：公司名（L3）| 职位（L4）| 时间（L5）
- 正文 2–3 条 bullet，**每条以加粗的四字短语开头**（如「AI 内部提效：」「用户兴趣洞察：」「创作者生态运营：」）
- 每条 bullet 1–2 行，整段合计不超过 6 行
- 时间格式统一 `YYYY.MM-YYYY.MM`，用半角连字符

### 5.3 项目经历

- 条目头三列：项目名（L3）| 角色（L4）| 时间（L5）
- 正文 1–2 条 bullet
- **项目名要带辨识度**：产品名用书名号「」，竞赛写全称 + 奖项等级
- 角色写实际身份（独立开发者 / 队长|建模手），不写"参与者"

### 5.4 校园经历

**必须有，不能删。** 这是结构性的——缺了它，整份简历读起来像只有三段实习，人物不立体。

但可以精简：条目头一行 + 2–3 行 bullet，只保留与目标岗位相关的部分。绝不能整块删除来给别处腾行数。

### 5.5 个人总结与专业技能

2–4 行。第一句给定位（背景 + 核心能力 + 方向），后面列工具与方法。AI 相关技能至少保留一个。

---

## 六、字体

- 中文：微软雅黑；西文与数字跟随同族（微软雅黑自带拉丁字形）
- 交付 PDF 必须嵌入字体，不依赖阅读器本地字体
- 9pt 是正文下限，**不得为了塞内容降到 8.5pt**——低于 9pt 打印发虚，HR 屏幕上看更糊

---

## 七、加粗规则

**只加粗成果数据**：

- 百分数：`80%` `35%` `15%` `20%`
- 比率：`4.8/5`
- 倍率：`3 倍`

**不加粗**：人数、位数、次数、份数、条数（`45 人` `10+ 位` `7 次` `80+ 份`）。这类计数一多，满屏黑体，反而没有重点。

**不加粗**：小标题以外的正文、公司名（公司名本身已是 L3 加粗，不重复处理）、时间。

---

## 八、行数与末行填充（本次新增，重点）

### 8.1 行数预算

一页可容纳正文约 **48 行**（实测）。分配基准：

| 区块 | 行数 |
|---|---|
| 姓名 + 联系方式 | 4–5 |
| 教育背景 | 4–5 |
| 个人总结与技能 | 2–4 |
| 实习经历（3 段） | 15–18 |
| 项目经历（2 段） | 6–8 |
| 校园经历 | 3–4 |

### 8.2 末行填充率（解决"半行显空"）

对**每一条 bullet**：

```
行数 = 向上取整(字符数 ÷ 每行容量)
末行填充率 = (字符数 - (行数-1) × 每行容量) ÷ 每行容量
```

要求 **末行填充率 ≥ 60%**。

低于 60% 的处理顺序：

1. **压行**：删虚词、合并短句，把 2 行压到 1 行（前提是信息不丢）
2. **补满**：加一个具体信息（数字、方法、范围），把末行撑到 60% 以上
3. **重写**：换句式让长度落在合适区间

**禁止**：靠加空格、加形容词、拉长句子的方式凑字。

### 8.3 不允许出现的形态

- 1.2 行的 bullet（第二行只有几个字）——最难看
- 三行以上的 bullet——一条 bullet 最多两行
- 同一区块内 bullet 行数参差过大（如 1/2/3 行混排）

---

## 九、照片

- 位置：右上角，约 90 × 120 pt，白底或浅蓝底证件照
- 只做**有照片版**（用户已确认）
- 照片区右侧与正文右边界对齐
- 文件体积 ≤ 200 KB，格式 JPG

---

## 十、导出与校验（量化清单）

导出后必须逐项通过，任一项不达标即回退：

| # | 校验项 | 通过标准 |
|---|---|---|
| 1 | 页数 | = 1 |
| 2 | 底部留白 | 40–90 pt |
| 3 | 首行 y | 780 ± 3 pt |
| 4 | 总行数 | 46–50 行 |
| 5 | 字号种类 | 恰好 6 种 |
| 6 | 日期右边界 | 偏差 ≤ 2 pt |
| 7 | 末行填充率 | 所有 bullet ≥ 60% |
| 8 | 加粗项 | 只命中百分数/比率/倍率 |
| 9 | 字体嵌入 | PDF 内嵌，无字体缺失警告 |
| 10 | 视觉回归 | 与原版逐区块对比，无位移、无溢出 |

**校验方式**：不靠估算，导出后用 pypdf 实测坐标；末行填充率按渲染后的实际换行位置计算，不按字符数估算。

## 十一、模板标定（两条起点）

第一节到第十节描述的是一套**已经标定好的模板**。但别人用这个插件时，起点只有两种：手里已有简历，或者什么都没有。这一节定义两种情况怎么走，以及标定完怎么锁定。

**总则：模板只标定一次。** 标定结果写入 `profile.template`，之后所有投递只读它，不再重复分析。改模板必须用户显式提出。

---

### 11.1 情形 A：用户要用自己的版式

#### A0 准入条件（先检查，不满足就不接）

**必须同时提供 docx 与 pdf，缺一不可。** PDF 定版式基准（打印出来长什么样），docx 作为编辑源（微调只改它，再重新导出 PDF）。

| 用户提供的 | 处理 |
|---|---|
| docx + pdf，内容一致 | 接受，进 A1 |
| docx + pdf，内容对不上 | 停下来问以哪一份为准 |
| 只有 docx | 请用户导出 PDF 补上（对方几分钟的事） |
| **只有 PDF** | **不接受**，说明原因，给两条出路（见下） |
| 扫描件 PDF（抽不出文本） | 不接受，同上 |

**只有 PDF 为什么不接**：PDF 里的文字是固定坐标，不是可重排的段落。改一个字就可能挤出边界、断行错乱，改完的成品无法保证与原版一致——而这份 PDF 是要给 HR 打印的。

给用户的两条出路：
1. 找到原始排版文件（Word / 设计源文件）导出成 docx 发过来
2. 用内置模板重排一版

**内容一致性校验**：两边各抽全文，比对主体内容。段落数量、公司名、时间区间对不上就判定不一致，问用户以哪份为准。手滑发错版本很常见。

#### A1 判 docx 的可编辑性

| 类型 | 判定特征 | 处理 |
|---|---|---|
| 原生 docx | 段落数正常、文本框 < 10、文件 < 100 KB | 直接改段落，最稳 |
| PDF 倒推的 docx | 文件 2–3 MB、`txbxContent` 出现 50 次以上、文本块远多于段落 | 提示风险，建议用户提供原始排版文件；用户坚持则走 XML 层，并先清查编辑残留 |

判定方法：读 `word/document.xml`，统计 `<w:p>`、`txbxContent`、`<w:tbl>` 三类节点数量。文本框多于段落，就是 PDF 倒推的。

**遇到 PDF 倒推版要说的话**：

> 这份 docx 像是从 PDF 转出来的，文字都塞在文本框里。能改，但改起来容易带出转换时留下的痕迹。你手上如果有原始的 Word 文件，用那份更稳。


#### A2 解析结构，产出模板档案

**PDF 定版式，docx 定结构。** 版式指标（边距、字号、行距、坐标）从 PDF 量，因为 PDF 是最终呈现；区块组成和文字内容从 docx 读，因为 docx 才是要改的东西。

按固定字段抽取，抽不到就标 `null`，不许猜：

- 纸张尺寸、上/下/左/右边距
- 字号层级表（每个字号 + 出现次数 + 典型样本文字）
- 三种间距：正文行距、条目间距、区块间距
- 区块顺序与区块清单（教育/实习/项目/校园/技能/其他）
- 每个区块的内部结构（一行式还是两段式、条目头几列、bullet 几条）
- 分栏与对齐方式（单栏/双栏、时间是否右对齐、右边界坐标）
- 每行容量（取 20 行正文的平均字符数）
- 总行数与首末行坐标
- 照片：有无、尺寸、位置
- 现有加粗策略（加粗了什么、加粗了几处）
- 字体族

#### A3 生成标定报告给用户看

报告必须包含三块，缺一不可：

**结构摘要**：几个字号层级、几个区块、区块顺序、有无照片、总行数。

**三项判断**：可编辑性属于哪一类；是否严格一页；刚才提到的编辑残留，有几处、长什么样。

**三项风险**（发现了就直说，不能只挑好的说）：
- 字号层级超过 6 种 → 版面会散
- 间距不一致（同层级用了两种行距）→ 打印出来会看出歪
- 缺结构区块（比如没有校园经历、没有技能行）→ 结构不完整

#### A4 与用户确认（逐条回答，不合并）

1. 之后所有投递是否都沿用这份模板？
2. 有没有要改的？——字号、留白、区块顺序、增删区块，逐项问，别用"有要改的吗"一句带过。
3. 照片保留吗？（决定后续是否自动带照片位）

#### A5 锁定

用户确认后写 `template.locked = true`，并把报告存为 `template-report.md` 留档。

---

### 11.2 情形 B：使用内置模板（默认路径）

#### B1 先做出样例，不要用文字描述

必须生成一份**脱敏样例 PDF**（虚构姓名、虚构学校、虚构公司、保留真实结构），导出后截图给用户看。用文字说"一页、六字号、时间右对齐"用户没有概念，看到才算数。

#### B2 展示时讲清四条特点

- 一页、单栏、时间右对齐，扫读时视线不用跳
- 六个字号层级，层级少所以不乱
- 技能区块刻意放在实习之前，让能力标签先被看到
- 教育背景一行式，获奖跟在该校下面（不拆两行，省行高）

同时说明我们知道的问题：这套模板**有照片位**，如果用户投互联网或外企、或者没有证件照，需要确认是否去掉。

#### B3 询问四个问题

1. 用这套模板吗？
2. 字号看着合适吗？（9pt 正文，偏小但能塞下三段实习）
3. 照片位留还是去？
4. 你的经历够几个区块？（决定是否要砍区块换行数）

#### B4 确认后实例化，再做第二次确认

**结构确认和内容确认必须分开**。先让用户确认"骨架就这样"，再用他的真实信息填进去，然后让他确认"内容对不对"。一次确认两件事，用户会漏。

---

### 11.3 分支判定

```
用户想用自己的版式吗？
├─ 不想 → 情形 B（内置模板）
└─ 想 → 是否同时提供了 docx 和 pdf？
         ├─ 是 → 两份内容一致吗？
         │        ├─ 一致 → 情形 A
         │        └─ 不一致 → 问用户以哪份为准，再进情形 A
         └─ 否
              ├─ 只有 docx → 请用户导出 PDF 补上
              ├─ 只有 PDF  → 不接受，说明原因（改不了、保证不了一致）
              └─ 扫描件    → 不接受，同上
                            ↓
                     两条出路：找原始排版文件 / 改用内置模板
```

**默认进情形 B。** 内置模板对大多数人是更快的路，只有当用户明确说要自己的版式、并且能凑齐一对文件时才走情形 A。


---

### 11.4 两条路汇合

无论走哪条，最终都产出同一份 `template.json`，结构如下：

```json
{
  "locked": true,
  "source": "user_existing | builtin",
  "page": { "w": 595, "h": 842, "top": 62, "bottom": 52, "left": 50, "right": 545 },
  "fonts": { "cjk": "微软雅黑", "sizeLevels": [20, 10.6, 9.5, 9.0] },
  "spacing": { "line": 14, "entry": 16, "section": 19 },
  "sections": ["教育背景", "个人总结与专业技能", "实习经历", "项目经历", "校园经历"],
  "lineCapacity": 58,
  "totalLines": 48,
  "photo": { "enabled": true, "w": 90, "h": 120 },
  "boldPolicy": "percent_ratio_only"
}
```

后续流程只读这份文件，不再重复标定。

---

### 11.5 何时重新标定

- 用户主动换模板
- 用户说"这份排版不好看"
- 内容压到极限仍然溢出
- 用户投递的系统明确要求两页或特定格式

除这四种情况，不得擅自改动已锁定的模板。

## 十二、打印适配

PDF 有两个用途：**上传到招聘系统**，以及 **HR 打印出来看**。第二个用途经常被忽略，但它是拿到面试的第一道门——打印出来发虚、断层、色块糊成一团，再好的经历也显得业余。

以下十条是打印安全线：

| # | 要求 | 原因 |
|---|---|---|
| 1 | 字体必须嵌入并子集化 | HR 电脑没装微软雅黑时，会用默认字体替换，版式全乱 |
| 2 | 正文不小于 9pt | 低于 9pt 打印发虚，屏幕上也糊 |
| 3 | 分隔线、下划线粗细 ≥ 0.5pt | 发丝线在 600dpi 打印后常断成虚线 |
| 4 | 层级不能只靠颜色区分 | 黑白打印机是常态，浅蓝下划线印出来就是浅灰，必须靠字号、字重、缩进也能分出层级 |
| 5 | 左右上下边距 ≥ 40pt（约 14mm） | 激光打印机四周约 5mm 不可打印区，边距太窄会被切 |
| 6 | 不用大面积底色、不用深色块 | 费墨、易卡纸，复印后色差明显 |
| 7 | 照片 ≥ 300 dpi | 低分辨率照片打印后发糊，还不如不放 |
| 8 | 严格单页 | HR 常单面打印，第二页容易被漏看或丢掉 |
| 9 | 文件名含姓名与岗位 | `姓名 27秋招 - 公司名.pdf`，归档时不至于变成 `未命名(3).pdf` |
| 10 | 导出后做一次黑白预览 | 灰度查看一遍，确认层级仍然清晰 |

### 12.1 打印校验怎么做

导出 PDF 后追加两项检查，与第十节的十项并列：

- **字体嵌入检查**：用 pypdf 读字体字典，确认每个字体都有 `FontFile2` 或 `FontFile3` 条目；只有 `BaseFont` 没嵌入文件的，判失败。
- **灰度可辨检查**：把所有颜色转成灰度（或在阅读器里开灰度预览），确认区块标题、条目头、正文三层仍然能区分。区分不了，说明层级过度依赖颜色，回退改字重。

### 12.2 常见打印事故

- 浅蓝下划线在黑白打印后几乎不可见 → 加粗标题本身，别让颜色承担层级
- 文本框边界在转换时被撑大 → 导出后逐区块看有没有错位
- 照片带透明通道打印后出现黑底 → 照片必须扁平化为白底 JPG
